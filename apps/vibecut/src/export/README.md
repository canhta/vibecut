# Export settings and publication

`export/settings` renders `render::OutputOptions`: resolution presets keep canvas ratio, custom even dimensions change output only, and explicit frame rate, target bitrate, compatible codec and H.264 profile feed the renderer. Range is full by default, or frame-snapped in/out markers or the selected clips' bounds; range errors disable Export before any job is submitted. Scene scope is active by default, all, or a named scene. Preferences persist these choices plus the format, quality, audio switch and last directory; source consent and overwrite authorization stay transient. `Editor::dispatch` takes typed `ExportOptions` for `export.run`. Project and undo history never store export state. An empty timeline shows a catalog error and refuses start.

All-scene output is rendered as one staged batch, then saved scene by scene with distinct scene-id filenames through the native save workflow. Cancelling a save picker keeps the current and remaining finished files; closing the dialog discards them.

`export.run` / `export.retry` submit through engine's one export job path and share playback's byte budget. `export.run` writes only to a unique temporary output. Running output disables settings and shows engine stage, progress and Cancel; cancel or close clears the temporary output and returns to settings with no final file. Inspection exposes the job snapshot, phase, typed failure, missing/changed source diagnostics, consent, finished temp and attempt settings.

On completion the app opens the asynchronous native save dialog with the sanitized `<ProjectName>.<ext>` and last save directory. Filenames keep Unicode and spaces, replace invalid filesystem characters, trim trailing dots and spaces and escape Windows reserved device names. The filename and container filter follow the rendered attempt, even if format preferences changed meanwhile. `Editor::export_save_defaults` supplies the defaults; `Editor::export_picked_file`, `Editor::export_save_cancelled` and the `Workspace` picker inject native results. Cancelling the dialog writes nothing and keeps the finished job ready to save without re-exporting; closing the popover discards it.

Saving submits engine's completed-export publication job with the rendered snapshot and Autosave's protected project, metadata and recovery paths. Admission, copy and sync run on the runner through project's atomic stage. Progress and cancel stay in the dialog; cancellation before commit and failed staging or publication keep the finished render and the previous destination. Only confirmed publication persists the directory, toasts the path and closes the modal. Shutdown joins the runner before removing owned temporary files.

A refusal or failed attempt replaces progress with an inline typed error panel with text-only Copy and Retry. Retry reruns the same attempt settings into a new temp output, leaving a prior successful file untouched; publication Retry reopens destination selection without re-encoding. Retry refuses running, cancelled and successful attempts. A degraded retry needs an explicit toggle over the listed diagnostics; a project or audio-scope change clears consent. Consented degraded output follows the same save/toast/close path, with affected ranges disclosed before running and no post-completion warning. Tests inject production source failures at render's source-factory boundary.
