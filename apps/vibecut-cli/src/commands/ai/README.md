# AI commands

`subtitle` is the composition root of the [caption commands](../../../../../crates/engine/src/subtitles/README.md#caption-workflow-commands): it lends `CaptionAccess` (selected providers, `CliConsent` and the one models-cache handle), imports the input as asset 1 of an in-memory project and runs `captions.generate`, `captions.apply`, `captions.translate`, `retranslate`, then `export_subtitles`/`burn_subtitles` through the registry with a policy that authorises exactly the requested output paths. It resolves the language, runs the flag pre-checks and prints the result; it implements no chunking, consent/cost, transcription, translation, checkpoint or serialization logic. `subtitle` has no signal-to-job-cancel handler: interruption follows crash semantics, and completed ASR windows stay reusable through the content-addressed cache. `providers` and `model` expose the offline provider and model catalogs; the CLI prints local/remote capabilities and upload disclosures. Local models are never downloaded implicitly; `model download` requires `--yes-download` after printing the exact licence, source, size and hashes. A completed export or subtitle run reports its output paths, not render's detailed receipt.

`agent` is the CLI caller of the [agent crate](../../../../../crates/agent/README.md): it parses the flags, builds the provider adapter from the environment key, prints the disclosure on stderr and refuses without `--yes-upload`, then runs `run_turn` over the leased project and prints each event as one JSON line. The turn loop, tools, policy and limits stay in the crate; the command saves only after `--apply` replayed a finished turn through `Session::apply_fork`.

`chapters` and `fillers` adapt the engine's chapter and filler analysis jobs through the lent text provider. They parse flags, print the exact upload disclosure before any remote request, and map the returned document or candidates and typed refusals to stdout/stderr; segmentation, prompts, chapter snapping and filler matching stay with their engine owners.

`clips` is an adapter over the registry commands `clips.suggest` and `clips.export`, implemented by the [shorts workflow](../../../../../crates/shorts/src/suggestion/README.md) and lent through `CaptionAccess::with_clips` (selected providers, `CliConsent`, the one models-cache handle). It parses suggestion, ASR, translation and export flags, runs the commands (translation through `captions.translate` + `retranslate` over a caption item built from the suggestion's cues), waits for the per-short export jobs, and maps candidates or typed failures to stdout/stderr; consent prints the provider's upload scope before any remote byte leaves the machine. It owns no segmentation, prompt, selection, snapping or export logic, and `--provider` never falls back. Remote suggestion credentials are refused before media work. `providers --operation clips` lists the same offline catalog without opening an adapter. Boundary adjustment kinds follow the [CLI contract](../../../../../docs/product/agent-control/cli.md).
