# Domain docs

Read before exploring:

- `GLOSSARY.md` at the repo root.
- `docs/adr/`: ADRs touching the area you work in.

If either is missing, proceed silently; `/domain-modeling` creates them when a term or decision is resolved.

## Rules

- Use glossary terms in issue titles, proposals, test names and code. No synonyms the glossary avoids. A missing concept is either invented language (reconsider) or a real gap (note it for `/domain-modeling`).
- If your output contradicts an ADR, say so explicitly: _Contradicts ADR-0003 (…), but worth reopening because…_
