# Local Gipformer

Windows native builds use one dynamic MSVC CRT (`/MD`) with Rust and Whisper. The upstream Rust Sherpa downloader selects `/MT` archives, so xtask provisions the locked `sherpa-onnx-sys` version's static `/MD` release archive and passes its `lib` directory as `SHERPA_ONNX_LIB_DIR`. macOS uses the upstream static archive.

`cargo xtask sherpa [--arch x86_64|aarch64]` prefetches the Windows archive and prints its library directory. Direct Cargo builds outside xtask must set `SHERPA_ONNX_LIB_DIR` to it, with the normal FFmpeg environment; a supplied value must hold architecture-matched static `/MD` libraries. Provisioning verifies the GitHub release-asset SHA-256 and size before extraction and keeps an atomic cache receipt; incomplete caches fail with recovery guidance. The version comes from `Cargo.lock`. The [workflow](../../../../docs/engineering/workflows.md#ffmpeg-provisioning) owns build environment setup. Windows runtime acceptance is unverified.

The default `gipformer` feature includes the safe sherpa-onnx bindings and the `vibecut-local-asr` native runner binary. `gipformer::Gipformer::load` takes the pinned model, immutable cache directory, absolute shipped runner path, device/thread count and execution hooks. It verifies all four files with the shared integrity policy and starts a reusable native process. The app ships the runner next to its executable and passes its trusted absolute path.

`models::suggested_transcriber` returns the MIT Gipformer model for the Vietnamese profile and the multilingual Whisper suggestion for others. It never runs a provider, falls back or starts a download. Composition presents an explicit provider choice and obtains a download click via `DownloadConsent`; engine's model-transfer owner consumes the same catalog records.

CPU only. The released static runtime silently falls back from CoreML to CPU, so `Device::CoreMl` returns `Unsupported`.

Input is finite mono 16 kHz f32 PCM with absolute source offsets, at most five minutes. The runner decodes one 20 s chunk at a time, including the short tail. Engine owns longer recordings, speech-safe outer windows and reconciliation. Hard chunk boundaries can hurt quality; there is no VAD model. The settings fingerprint covers model hashes, native binding, chunk/decode policy, hardware request and thread count.

The native runtime runs outside the application process because it can write paths in diagnostics and terminate on native failures. Its stderr is discarded; private framed pipes carry bounded metadata, PCM and an explicit reply. One invocation per adapter; overlapping calls return `Unsupported`. Pool locks cover ownership changes only, never IO. Cancellation acknowledges once, kills and reaps native work and joins pipe threads before returning `Cancelled`, with no partial output. Hook unwinding also kills and reaps first. The next call replaces the stopped process. Poisoned locks fail with `Inference`.

Native RNNT token start points have no durations. The adapter keeps raw lexical bytes in ordinal order with explicit missing ranges and advertises no timing. It preserves the leading BPE space; any other difference from the runtime's text is an error. `Recognition::to_transcript` returns `TimingUnavailable` until an explicitly selected aligner supplies speech ranges; shared assembly then handles correspondence, forced provenance and tick conversion. Neither adjacent starts nor chunk ends become speech ends. Native timing MAE is unavailable.

Tests: `cargo test -p ai` includes Unix fake-process tests for OS pipe/kill/join behavior. The ignored `local_gipformer` test needs pinned weights and local speech. `cargo run --release -p ai --example local_gipformer -- MODEL_DIRECTORY RUNNER cpu THREADS AUDIO_F32LE...` benchmarks several inputs on one loaded model and prints JSONL recognition output. Performance, quality and accelerator acceptance need separate measurements.
