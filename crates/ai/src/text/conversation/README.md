# Agent chat conversation

One streamed tool-use conversation behind `ChatModel`, two adapters (`AnthropicChat`, `OpenAiChat`) over [`ai::remote`](../../foundation/remote/README.md) admission, and the per-conversation consent and spend ledger of the in-app agent. The turn loop, the tool set and the event stream belong to the agent crate; this module is the provider boundary under it.

## Surface

`Conversation` owns history, tools, the system text, consent and ledger. `send_user` and `send_tool_results` each stream one assistant message and return a `Reply`: text, the valid `calls` to run, `rejected` calls already answered, usage and the settled spend. Text deltas and finished tool calls also reach the caller's `on_event` closure while the stream runs. `Message`, `ToolCall`, `ToolResult`, `ToolSpec` and `Usage` are provider-neutral and serializable for the chat history the app keeps per project. The only provider state in a message is `Replay`, an opaque value (Anthropic content blocks with thinking signatures, OpenAI output items with encrypted reasoning) that only the adapter that wrote it can read; another provider refuses it with `Invalid`.

A reply with `needs_results()` owes `send_tool_results` exactly one `ToolResult` per entry of `calls`, in any order; the request keeps the model's order. A call with arguments that are not a JSON object, or to a tool that was not offered, never reaches the caller: the conversation writes an error result the model reads (`rejected`) and merges it into the next request. Tool results are data for the model, never instructions, and a result may only carry the `DataKind`s the consent names.

`truncate_history(len)` drops every message after the first `len` and forgets the tool calls still owed results, for a caller that abandoned a turn (cancelled, step limit, failed request); the ledger keeps what the dropped requests cost. `ScriptedChat` is a deterministic `ChatModel` that plays a fixed list of `ScriptedStep`s (a reply, a reply built from the messages sent so far, or a failure); its request body is the serialized history, so the ledger and context limits apply to it as to a real adapter. It is the test double of the [agent crate](../../../../agent/README.md), compiled only with the `test-chat` feature that crate's tests enable.

## Consent and ledger

`AgentChatScope` binds provider configuration (endpoint, model, settings), the allowed `DataKind`s and a USD spend limit; `AgentChatConsent::grant` is called by the composition root after the user accepted `disclosure(...)` (provider, model, kinds, limit, context and output ceilings, provider policy and pricing links). A changed provider, model, kind or limit is a different scope and needs a new consent. `Conversation::new` refuses without a consent for exactly its adapter's configuration, and for a model without a registered price, because a limit cannot be held against an unknown rate. Nothing before the stream touches the network.

Each request reserves its upper bound first: every body byte as an input token (a token is at least one byte) plus `max_output_tokens`, at the registered rate. A request whose bound passes the limit is not sent (`Cost`); a body above `max_context_bytes` is not sent (`Payload`). After the stream the reservation settles to the reported usage. A failed attempt settles to its full reservation when it may have generated (network loss, cancellation, a broken stream, `Incomplete`, `Refused`) and to zero when the provider refused it before generating (`Auth`, `Quota`, `RateLimit`, `ModelUnavailable`, `Invalid`, `Payload`). A failure leaves history untouched, so the caller retries by repeating the call; the retry reserves on its own, and the limit therefore also bounds retries. Adapters and the conversation never retry by themselves.

Known rates (checked 2026-11-12): Claude Sonnet 5.5 $2 / $10 and GPT-6.1 Sol $2 / $10 per million tokens, GPT-6 Astra $10 / $50, all for prompts up to 272K tokens, which `MAX_CONTEXT_BYTES` keeps the request under. `default_model` names the provider's current tool-use model; model ids stay settings. Steps per turn and the turn's typed end reason belong to the agent crate.

## Streams and errors

`Sse` is a bounded reader: 256 KiB per line, 8 MiB per stream, and a reply of at most 1 MiB of text and tool arguments, else `Payload`. Cancellation is checked before every provider event; observing it calls `ExecutionHooks::cancelling` and drops the connection. A stream that ends before `message_stop` or `response.completed` is `Incomplete`, as is `max_tokens`. Non-2xx statuses and in-stream error events map onto the existing `ai::Error` categories from the error type or code only; provider messages are dropped.

Anthropic: Messages with `stream`, `thinking: between_tools`, `tools`, `tool_result` blocks in the next user message, thinking blocks replayed unmodified. OpenAI: Responses with `stream`, `store: false`, function tools (`strict: false`, the registry schemas are validated by the tool owner), `parallel_tool_calls`, `include: reasoning.encrypted_content`, `function_call_output` items by `call_id`; an error result is sent as `error: <text>` because the item has no error flag.

Sources checked 2026-11-12: Anthropic [streaming messages and tool use](https://platform.claude.com/docs/en/api/messages), [pricing](https://platform.claude.com/docs/en/about-claude/pricing); OpenAI [function calling](https://developers.openai.com/api/docs/guides/function-calling), [Responses streaming events](https://developers.openai.com/api/reference/resources/responses/methods/create), [GPT-6.1 Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol), [pricing](https://developers.openai.com/api/docs/pricing). Fixtures are authored from those shapes, not recorded; live behaviour, billing and the 120 s transport timeout on a long stream are unverified.
