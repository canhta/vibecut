# Session

Interface: `Session`, `Command`, `CommandKind`, `registry`, `JobTarget`, `transcript`, `CueId`, `WordId`, `wire`.

## Public entry points

`Session::new(project, history_limit)` admits 1..=1000 retained undo steps. `project()` exposes an immutable `Arc<Project>`. `apply(Command)` and `execute(command_id, serde_json::Value)` run the same edits. `apply_merged(command, Some(key))` combines consecutive successful changes into one undo step for a continuous gesture; call `end_merge()` at gesture end. Undo, redo, an explicit boundary or a different key ends merging. Refusal or unwind restores the previous merge state. A no-op with a different key ends merging without changing project or history. Keys are 1..=256 UTF-8 bytes. Call `end_merge()` at save and selection changes; finish or cancel explicit gestures before those actions. History eviction removes the oldest undo snapshot; it never splits a batch. A changed edit clears redo; failures and no-ops preserve redo. Undo/redo move existing snapshots, preserving exact integer timing and media and caption identity.

`registry()` derives JSON Schema 2020-12 input schemas, output schemas, effects, labels and executable examples alongside `Command` from one declaration. Leaf shapes come from the owning types; fixed objects are closed recursively, including empty params and nested batches. Each standalone parameter schema keeps only its transitively referenced definitions so the catalog stays within the response byte budget. Domain constructors still validate invariants. `CommandSpec::enabled(session)` describes coarse availability.

Each declaration line also carries per-command facts once, outside the wire catalog and its digest: an `Availability` rule (default `Always`), a `GrantClass` (`Agent`, `Output` for the sole file-publishing commands, `Human`; defaults by effect and required for session and job control, so a missing class fails the registry test), the `curated` MCP flag and the `Lifecycle` route of the five library/persistence commands. `lifecycle(id)` is the one routing answer adapters share (`Session::control_routed`, `Autosave::execute`, CLI `exec`); batch and candidate refusal of non-edit commands derives from the declared effect. A new publishing command also needs its `Command::published_path` arm (the registry test checks). `CommandKind` is the parameter-free identity generated by that declaration; `CommandKind::id()` supplies the dispatch id and `enabled(session)` delegates to the declared availability rule. `Command::kind()` exposes the same identity for typed commands, so adapters never need a second engine-id list.

Required nullable keyframe fields stay required; `NewItem.source_asset` may be omitted or null. JSON integer admission is limited to ±(2^53−1), including nested values. ProjectId has one decimal-string encoding at its owner, including project persistence; other IDs and Tick remain numbers.

`execute("timeline.add_track", {"name":"Video", "kind":"video"})` returns `Outcome { changed, created }`. `created` lists engine-allocated typed track, item and bookmark IDs in execution order (including batch children). IDs share a checked increasing counter initialized above all loaded track, item and bookmark IDs. They are not reused after delete, undo, branching, cancelled previews or rolled-back groups within a Session. Media supplies asset identity; `import.add_asset` registers a validated SourceAsset and does no probe or hash IO. A failed command or batch consumes no IDs; successful preview and group children retire their IDs even when their outer operation rolls back. ID exhaustion returns a typed error. Reloading a project starts a new Session and identity lifetime.

## Transcript read model

`Session::transcript()` returns the active scene's caption cues in output time, each with its item and track, source/target texts, `protected` (the cue's source text was explicitly edited) and `locked` (the owning track) flags, and its measured words. A `TranscriptWord` carries a `WordId` (`item`, retained `cue`, `word` index into the cue's ranges), the paired source token when token and timing counts agree, its output range and the same flags. A `CueId` addresses one caption cue by `item` and retained `cue` for cue edits. It reads `Item::word_spans`, so a trimmed item clips its words instead of duplicating a source range, and repeated source spans produce one entry per item occurrence. The view is a read: it changes no project, revision or history. Selecting a `WordId` or `CueId` from another scene is addressable by the command path, which refuses it with `SceneBoundary` rather than cutting two timelines.

## Filler candidate read model

`timeline.filler_candidates {language, include_markers}` runs the captions lexicon detector over every caption item's visible cue track, so a candidate always names output ranges the timeline shows. Each result carries its id (`filler:<item>:<cue>:<source word start>`), caption item and retained cue, output range, `filled_pause`/`discourse_marker` kind and the cue's `edited_cue` flag; filled pauses are the default and markers require `include_markers`. An unknown language is a typed refusal; cues without measured words contribute nothing, and a candidate whose words are all outside a trimmed item's output span is absent. The query is a read: it changes no project, revision or history, and it refuses during a gesture or group because it reads committed output. `timeline.remove_fillers` resolves the same ids through a fresh detection, so an id that an edit, trim or merge made stale refuses rather than cutting a different word.

## Transactions, gestures and changes

`begin_gesture`, `commit_gesture` and `cancel_gesture` are registered commands with matching typed methods. During a gesture `project()` exposes validated preview snapshots, while original undo/redo and pending committed changes stay untouched. Commit adds one undo step, evicting at most one oldest step; cancel restores the entry snapshot and pending event without adding undo/redo. Starting or ending a gesture breaks merge continuity. A no-op gesture preserves redo and emits no committed-project event; its closed preview lifetime advances the control revision. A refused preview command leaves the prior preview and gesture intact.

`transaction(|session| -> Result<T>)` stages several commands with the same history and event rules. Success commits one step; error or unwind restores its entry project, undo/redo, merge state and deferred event. The history limit is never raised; staged edits do not evict history. Nested gestures or groups, and undo/redo inside them, return typed errors. Only engine state is transactional; external effects performed by the caller's closure are outside it.

`take_change()` drains a single coalesced committed-project snapshot. It returns None during previews and groups, including for an older undrained event. Commit publishes one change; cancellation or failure restores the previous pending event. Consumers render previews from `project()` and use committed changes for persistence and processing. Begin, commit and cancel return no newly created IDs; individual preview commands return their provisional IDs.

Commands and groups catch unwinding panics, restore their engine state and return `EditError::Panicked` without formatting payloads. Aborts, OOM and double-panic termination cannot be recovered. The application owns panic-hook policy. Errors preserve project, history, merge state and undrained changes; successful undo/redo always breaks merging. App presentation, scopes and preferences are not Session state.

## Project lifecycle and view state

`Session::create(Command::CreateProject { id, name }, history_limit)` consumes the registered `project.create` command and uses project's default canvas and timeline. `project.rename` is an ordinary edit with undo/redo. `project.set_view_state` requires `zoom`, `scroll` and `playhead`; it validates through project and changes only `Session::metadata`, outside project undo and committed-project notifications. View changes are refused inside gestures, groups and batches. `restore_metadata` loads the optional sidecar at open and is also refused during transactions.

`Autosave::open` reads metadata after acquiring its writer lease. Its background save writes the project and then the sidecar before publishing a receipt. `Autosave::execute("project.save", {})` queues the registered save; callers must poll or flush and check acknowledgement. `Session::execute` refuses create and save because they need lifecycle ownership. Destination admission refusals before a persistence job starts (including Busy, unsupported names and lease IO errors) return their typed error without poisoning the active autosave owner; choosing a different destination can succeed. Once a job is admitted, publication and worker failures follow the sticky error policy.
