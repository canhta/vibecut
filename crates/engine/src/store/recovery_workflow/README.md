# Session recovery and save acknowledgement

## Session recovery and save acknowledgement

`recovery::Autosave` composes one Session with persistence. Supply a private root under the app data directory, the aggregate ByteBudget and a monotonic jobs Clock. It uses JobRunner for off-thread encoding and IO, with one in-flight job and one latest pending snapshot. `apply(Command)` is the typed lifecycle entry: `Command::lifecycle()` sends save and thumbnail to this owner and every other command to `Session::apply`; `session_mut()` dispatches commands and gestures; `switch()` flushes before replacing it with never-saved work; to replace it with a saved file, flush first and construct `Autosave::open`. Each observed committed snapshot advances a checked session-local revision; gesture previews are never journaled.

Call `tick()` from the app event loop. `Schedule::default()` uses 800 ms debounce and 10 s maximum dirty age, measured from the first unpublished edit, including continuous editing. These are scheduling deadlines: event-loop latency, budget pressure and filesystem latency add to completion time. A write reserves 40 MiB from the shared budget before encoding bounded project and metadata bytes; budget starvation can delay admission.

One atomically created directory and exclusive std OS file lock identify each session. Live sessions (including other windows in one process) are never offered by `discover()`. After process death the OS releases the lock; discovery holds it until the returned Candidate is dropped or discarded, so two instances cannot claim the same abandoned session. Unsupported locking is a typed error, never assumed stale. Dropping an Autosave (after worker shutdown) or Candidate explicitly unlocks its session, even while a concurrently spawned child retains an inherited descriptor before exec. Scanning is bounded to 10,000 entries; corrupt candidates yield retained typed diagnostics, without deleting their files. Names and paths have no Debug representation and are never logged.

The journal descriptor has its own version, project id and name, original saved path, monotonic revision, BLAKE3 digest, timestamp and canonical snapshot filename. Project content uses only project::encode/decode and project::autosave::save, with two retained snapshots. The descriptor is committed through the shared atomic writer after its snapshot. Any write failure is sticky and prevents further rotation; an interrupted or failed descriptor update leaves the previous confirmed pair readable. The last published revision survives forced process termination; physical power loss and Windows runtime behavior are unverified.

`Autosave::new(root, session, budget, clock, schedule)` accepts never-saved or recovered work. `Autosave::open(root, path, history_limit, budget, clock, schedule)` acquires the project-owned WriterLease before loading or exposing an editable Session and keeps that lease through editing and background saves; opening is blocking IO and belongs off the UI thread. Busy or unsupported acquisition exposes no editable session. Project owns all locking and publication; engine transfers those capabilities to and from its worker without holding a state mutex across IO. Worker error or unwind retains the capabilities until the failed Autosave is dropped; Drop joins and cancels workers before releasing their leases.

`Candidate::recover()` returns never-saved work for `Autosave::new`; `save()` then returns SaveAsRequired. `save_as(path)` acquires the destination before queuing journal publication and project saving on the worker, and keeps both source and destination leases until acknowledgement. Ordinary save and aliases reuse the before-load lease. Save As requires an absolute native path; saves inside recovery storage are refused. Paths in journals and save receipts are canonical native paths; non-UTF-8 descriptor paths return a typed unsupported encoding error without changing the original file. Native path resolution and lease acquisition can block the caller; serialization and publication run on the worker.

`tick()` acknowledges only the captured Session target and its project SaveReceipt. `saved_receipt()` exposes the last acknowledged canonical path and exact published content hash; it is absent after open and invalidated by a stale completion. `saving()` includes a request queued behind an earlier journal or cleanup, and stays true through the worker's journal retirement after acknowledgement.

A stale completion returns StaleResult and invalidates the clean baseline: the worker has already written its snapshot, so even undo to the previously saved Arc stays dirty and recoverable. This also covers aliased save destinations; a fresh acknowledged save restores the clean baseline. A stale save-as releases the destination lease and never adopts its path or receipt; the existing saved path keeps its source lease.

An acknowledged Save As transfers path, receipt, fresh ProjectId and destination lease together. The worker journals the original snapshot before attempting publication, so a completed Save As leaves no recovery entry under the original identity. Later dirty snapshots use the new identity and path. A failed publication keeps the original identity, path and lease. The Session keeps its undo/redo history; restoring a historical snapshot keeps the current ProjectId, so undo cannot return to the original project.

`flush()` is an explicit blocking barrier for project switch and exit; IO still runs on the worker. `switch()` flushes and acknowledges the pending revision before replacing the project; failure keeps the old Session. Active gestures and groups refuse these boundaries. Drop joins and cancels existing work and does not promise a flush. Clean saves and undo-to-saved retire obsolete journals on the worker. `Candidate::discard` removes only its descriptor and canonical snapshots, preserving original projects and unrelated files. Empty session directories and lock files are retained; applications should archive or remove empty private session directories during maintenance before the scan cap.

The app owns recovery presentation and user choices.
