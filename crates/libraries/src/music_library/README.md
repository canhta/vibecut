# Music library

`music.search` calls the open aggregator's audio endpoint with `category=music`, `license=cc0,by`, bounded `page`/`page_size` and `filter_dead=true&mature=false`; free text goes through `q` and a genre or mood chip through `tags` (the two cannot be combined). Transport family/version fields compose only the display spelling; [project Music provenance admission](../../../project/src/model/README.md#music-provenance) owns the accepted identities, matching deeds and text/URL/duration limits. Malformed rows drop independently of valid siblings, including wrong JSON field types or missing attribution. Every accepted result carries title, author, licence, licence URL, attribution, source page and audio URL.

`MusicResult::library_music` returns checked NFC project provenance or `MusicError::Project` retaining the typed admission cause with static diagnostics. Remote conversion, public save, current Saved JSON reopen and both add paths use this same admission before cache/media access or mutation. Save and reopen retain the checked NFC text in the returned local record. Identical saves retain the original time and perform no publication; changed records publish atomically before replacing memory. Library JSON is read through a 1 MiB + 1 byte ceiling even if the file grows after metadata inspection. Unsupported envelope versions drop without interpreting their semantic body; malformed current-version envelopes return `LibraryCorrupt`, while invalid provenance retains its project cause. These non-persisted checks change neither the library format nor project schema.

Anonymous requests need no credential; `MusicToken::from_env` reads `OPENVERSE_API_KEY` for the optional user key that raises the source rate limit. The key is held in memory, sent only as a bearer header on the JSON request, never placed in a URL, and Debug is redacted. Anonymous pages are capped at twenty results and 240 results deep by the source; the request bound is twenty per page for every caller, so a key changes no page contract.

`music.search`, `music.save` and `music.unsave` are library operations, not Session edits: they never enter undo and callers run remote work off the UI thread. `music.add_to_timeline` is the registered edit (one undo step). `MusicLibrary::with_control` serves the three library commands from one adapter; its optional remote resolver is the scoped approval for a deliberate human remote search, so Saved, save and unsave never resolve a credential.

`MusicLibrary` retains [owned directory guards](../../../project/src/persistence/README.md#atomic-files) for its canonical root and real `audio` child, plus the existing project writer lease. Root aliases resolve once; child aliases/reparse points, replacement and unavailable identity refuse. `root()`/`cache_path()` only project paths; filesystem operations revalidate guards and lease. Sharing uses one `Arc<MusicLibrary>`; another handle/process receives Busy.

A nonblocking atomic operation token serializes local save/unsave/clear, cache reads/stores and whole direct/submitted transfers. Direct/local contention returns `MusicError::Project(Busy)`; submitted contention is the shared runtime's `CacheBusy` through `engine::control::Error`. Queued work owns its library admission from acceptance through retries/backoff until terminal/drop, while synchronous calls borrow it. There is one library admission truth across independent downloaders. Nested transfer/probe/publication/cleanup uses its existing proof, never reacquisition. State mutexes cover snapshots/commits only, never network, probing or I/O; Saved/local search remain readable. Catalog publication validates again in the atomic writer's final callback, then commits memory before unreferenced cache cleanup. Publication refusal preserves prior bytes/list/cache. Cleanup failure is typed **after catalog commit**, with remaining cache files; callers inspect Saved before retrying. Identical saves retain their record/time without publication.

`clear_all` preflights at most 10,000 total audio-child entries with fallible candidate growth, then publishes the empty catalog before cleanup. Only real regular canonical names of 64 lowercase hexadecimal bytes plus `.audio` are owned artifacts. Notes, controls, `.part-*`, malformed/uppercase names, symlinks/junctions and subdirectories are preserved. There is no recursive deletion or project-media cleanup. Unsave/URL invalidation delete only the exact unreferenced owned artifact; unknown entries remain. Failed enumeration/admission/catalog publication changes nothing; cleanup errors leave the committed catalog with remaining artifacts.

Preview bytes are staged, probed, and published only after validation through project's atomic writer. The cache key includes the exact audio URL. Search responses are capped at 1 MiB, library files at 1 MiB and 512 entries, audio at 32 MiB; `CachedMusic::bytes` reads through a 32 MiB + 1 byte ceiling and checks actual size. Directory checks are advisory boundaries, not arbitrary noncooperating post-check race protection. Returned `CachedMusic` data remains the existing public path/probe record.

`MusicDownloads` streams through the runner (`JobKind::SoundDownload`, network retries) with bounded redirects, existing HTTPS admission, content-length checks, cancellation checks before/after reads and a publication fence; no credential is sent to audio/CDN URLs. A part becomes owned only after successful `create_new`; collision objects are preserved. Normal failure removes only that owned part after guard/lease validation. Cleanup failure takes precedence over cancellation/network/media/response errors; an original project/IO cause keeps precedence, including failed publication callbacks. Such failures may retain an unpromoted part. Panic unwinding attempts owned cleanup best-effort, and the direct scope/runner terminal releases admission; cleanup is never claimed successful when it could not be reported.

The final callback validates identity/lease/target immediately before rename. Pre-seal cancellation publishes nothing; after a successful sealed rename, late cancellation is ignored. The already probed/hashed record is returned with its new path, without another fallible probe after commit. Callback project/IO failures remain their typed cause, never Cancelled. Directory validation remains advisory, not arbitrary noncooperating post-check/leaf-replacement or physical power-loss protection. Full hostile-stream/redirect boundary evidence is separate from these lifetime/fence guarantees.

`music.add_to_timeline` copies the cached file into project-owned media under its content hash (staged, hash-verified, then published through project's destination-admitting atomic writer; reused when present) and commits it plus the audio item in one undo step; the item stores `sourceType=music` metadata with title, author, licence, licence URL, attribution and source page. `MusicPreview` composes the cache/download owner with the app-owned preview sink; play and stop are cancellable and a missing device is a typed error.

The genre and mood chips in `CHIPS` are source tags, each sent as `tags=`; the panel labels a chip with the tag itself. Nothing is bundled or mirrored: search, preview, user-initiated save and local cache only.

Container export writes deduplicated attribution, licence, licence URL and source records from every music item into the MP4/WebM `comment` tag through media's bounded muxer metadata seam.
